# dev seed データカタログ（#591）

開発環境（`pnpm db:seed` → `prisma/seed-dev.ts`）が投入する、見積作成〜申請〜承認フローの
手動確認・デモ用データのカタログ。フィクスチャは `prisma/seed-dev-data/` 配下に分割している。

- `products.ts` … 商品・共通販売単価・原価・得意先別/納品先別上書き
- `estimates.ts` … 未申請の見積（ドラフト）
- `applications.ts` … 見積申請（5 状態）

> **用語注記**: イシューの「見積もりドラフト」は、正準語彙では **「バリエーション申請状態が
> 未申請の見積」** を指す口語。ここで作るドラフトは申請前の見積そのもの（`EstimateApplication`
> を持たない）で、申請するとどの承認段階／免除理由になるかは金額と申請者で決まる。
> （CONTEXT.md へ新語は追加しない方針。）

## 金額帯 × 承認段階（税込）

承認要否ポリシー（`ApprovalRequirementPolicy`）は **税込金額** で判定する。
税込 = 税抜小計 + floor(税抜小計 × 0.1)（`ROUND_DOWN`）。

| 税込金額             | 承認ゴール役職 | 備考                       |
| -------------------- | -------------- | -------------------------- |
| 10 万円未満          | —（免除）      | 免除理由 `BELOW_THRESHOLD` |
| 10 万〜100 万未満    | 課長           |                            |
| 100 万〜1000 万未満  | 部長           |                            |
| 1000 万〜3000 万未満 | 本部長         |                            |
| 3000 万以上          | 社長           |                            |

金額に依らない免除（`ApprovalRequirementPolicy` が上から順に判定）:

- `AFTER_REPAIR` … 事後見積（A 接頭辞・事後修理詳細つき）
- `CONSUMABLE_ONLY` … 消耗品のみの見積（金額無関係・ADR-0004）

## 申請者別チェーン段数（設計判断 B）

チェーン形は「申請者の上位役割」を起点に、金額で決まるゴール役職まで積み上がる（ADR-0003:
常に上位承認を求める）。同じドラフトでも **誰で申請するか** で段数が変わる。

| 申請者（課員） | 起点（上位役割）        | 課長ゴール | 部長ゴール | 本部長ゴール | 社長ゴール |
| -------------- | ----------------------- | ---------- | ---------- | ------------ | ---------- |
| 営業 課員      | 営業一課長              | 1 段       | 2 段       | 3 段         | 4 段       |
| 製造 課員      | 製造一課長              | 1 段       | 2 段       | 3 段         | 4 段       |
| 検証 課員      | 上位役割未設定 検証課長 | 1 段       | **不成立** | **不成立**   | **不成立** |

- 「不成立」= `GOAL_UNREACHABLE`。検証課員は上位役割エッジが欠けた課長を起点に持つため、
  部長以上のゴール金額で申請するとチェーンを組めず、申請時にエラーパスを画面確認できる。
- 役割持ち本人（例: 小林 九一＝営業一課長）で申請すると起点は自役割の上位（営業部長）になり、
  段数は課員より 1 段浅くなる。

## 申請 5 状態の分布（`applications.ts`・計 41 行）

状態は保存せず終端イベント行の有無で導出する（ADR-0058）。

| 状態      | 件数 | 見積番号帯                         | 主な弁別軸                          |
| --------- | ---- | ---------------------------------- | ----------------------------------- |
| PENDING   | 13   | `N9906101〜112`＋再申請 `N9906160` | 承認待ち役割（新規/途中承認で分散） |
| APPROVED  | 8    | `N9906120〜127`                    | 全ステップ承認済                    |
| REJECTED  | 7    | `N9906130〜135`＋差戻 `N9906160`   | 差戻段（課長/部長/本部長）で分散    |
| WITHDRAWN | 6    | `N9906140〜145`                    | 取下（うち 2 件は無効バリ）         |
| EXEMPTED  | 7    | `N9906150〜154` / `A9906110〜111`  | 免除 3 理由（下限3/消耗品2/事後2）  |

> `N9906160` は同一バリに attempt1 差戻 → attempt2 途中承認 PENDING を積んだリッチケース
> （詳細画面の履歴・差戻コメント・多段ステップ確認用）。

## 検索 8 軸の確認例

申請一覧（`/estimate-applications`）で、各軸を絞ると結果が変わるよう分布させている。

1. **見積番号** … `N99061` で申請系のみ、`N9906101` で 1 件に特定。
2. **得意先名** … 「山田製作所」（C001/D001）「東京電子」（C002/D003）「大阪機械」（C003/D006）等で分散。
3. **納品先名** … 「東京倉庫」（D001）「新宿本社」（D003）「梅田本社」（D006）等で分散。
4. **状態** … 5 値それぞれに最低 5 件。
5. **申請者名** … 「営業 課員」「製造 課員」「加藤 十郎」で弁別。
6. **承認待ち役割** … PENDING のみ。営業一課長 / 営業二課長 / 営業部長 / 営業本部長 / 製造一課長 /
   製造部長 / 社長 に分散（途中承認で承認待ち役割を弁別的にずらしている）。
7. **申請日時レンジ** … 本日（`daysAgo:0`）〜過去 90 日に分散。再シードで常に today 基準になる
   （ADR-20260629-3x5）。
8. **includeInactive** … OFF で `N9906141`・`N9906143`（取下・無効バリ）・`N9906153`（免除・無効バリ）が
   消え、ON で出る。

## 価格保守画面の確認用の例外（`products.ts`）

有効な価格保守対象商品へ共通販売単価＋原価を原則全付与しつつ、派生状態の確認台として例外を少数残す。

- 共通販売単価 **未設定** … `PRD016` / `PRD017`
- 共通販売単価 **失効**（過去で終了）… `PRD007`
- 共通販売単価 **期中改定履歴**（複数期間）… `PRD001`
- **得意先別 / 納品先別上書き** … 各 1 件（`products.ts` の `CUSTOMER_PRICE_OVERRIDES` /
  `DELIVERY_PRICE_OVERRIDES` を参照）
