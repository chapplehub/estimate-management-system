# Issue #509: 得意先別販売単価 保守画面のE2Eテスト — 実装計画

## 概要

得意先別販売単価の保守画面 E2E を実装する。共通販売単価 E2E（`common-selling-prices-detail.e2e.ts` / `common-selling-prices-crud.e2e.ts`）のミラー構成とし、以下の3ファイルを対象とする。

1. `customer-selling-prices-detail.e2e.ts`（新規・並列・DB不変）— 管理画面の閲覧系
2. `customer-selling-prices-crud.e2e.ts`（新規）— serial chain 3本＋重複拒否＋権限
3. `customer-selling-prices-list.e2e.ts`（既存・改修1件のみ）— href-only のリンクテストを実遷移テストへ昇格

一覧画面の E2E 本体は #508（PR #540）で作成済みのため**新規作成しない**。Issue スコープ「一覧→管理画面への遷移」の残作業は、#507 未着地ゆえ href 検証止まりだった既存テストの昇格1件で消化する。

規約準拠: 日付は today 相対（ADR-20260629-3x5・`jstRelativeDate`）、テスト内 Prisma 直接利用なし（ADR-0012）、行スコープセレクタ（ADR-0017）、chain 粒度・実行方式4分類（ADR-0020）。

## 設計判断

### 一覧画面ぶんのスコープ
- A. 一覧 E2E も新規作成する
- B. 既存の href-only リンクテスト（`customer-selling-prices-list.e2e.ts:170`）を実クリック→管理画面描画の検証へ昇格するのみ
- 採用: B（一覧は #508 で網羅済み。リンク切れ（動的ルート404）は href 検証では捕まらず、画面間結合の検証こそ両画面が揃った #509 の存在意義）

### 閲覧系（detail）テストの範囲
- A. 共通販売単価 detail のフルミラー＋得意先固有差分
- B. 得意先固有の差分のみ
- 採用: A（`PeriodDetailPanel` は共通版の同型写像だがコード非共有の別実装であり、得意先版だけが独立に壊れうる。閲覧系は並列＋DB不変で実行コスト増は軽微）

### 閲覧系シードの配置
- A. C902 に PRD866 を追加（一覧テストとシード共有）
- B. 閲覧系専用の得意先を新設
- 採用: A（閲覧系は DB 不変で干渉しない。一覧 E2E の assertion は行スコープのみで件数 assertion がなく、PRD866 追加で壊れないことを確認済み。PRD866 は現在有効を持つため `filter=none` / `filter=lapsed` の結果にも入らない。共通側でも一覧・詳細が PRD820 を共有しており既定パターン）
- 注意: 商品名に `得意先単価_` プレフィックスを付けると一覧テストの `name=得意先単価` 絞り込み結果に現れる（壊れないが結合が生まれる）。シードコメントにその旨を明記する

### CRUD chain 用データの隔離単位
- A. C902 に専用商品を追加
- B. 専用得意先 C903 を新設（`E2E専用_得意先別単価CRUD商事`）× 専用商品 PRD867〜869
- 採用: B（一覧画面は得意先スコープのビューなので隔離の自然な単位は商品ではなく得意先。A は現状壊れないが、将来件数 assertion 等が入ると並列実行時のみ flaky になる潜在的な罠。共通販売単価で読み系 PRD820 と変更系 PRD822/824/825 の帯を分けたのと同じ構図の複合キー版）
- C903 の商品に既存 PRD86x を使い回すことも技術的には可能だが、シードコメント上「PRD86x＝一覧用」の意味が濁るため専用商品を切る

### タイムライン検証の粒度
- 構造 assertion（testid の個数・存在・テキスト）まで。見た目（帯の横位置・幅・配色・破線）は検証しない
- 理由: `PriceTimeline` が主従レーンを別 testid（`price-timeline-bar` / `price-timeline-secondary-bar`）で区別しており構造検証が可能。幾何・配色は `_shared/timeline-layout` のユニットテスト責務で、E2E が CSS 数値に依存すると today 相対シードのたびに壊れる flaky 要因になる

### 対象外（crud ファイル冒頭コメントに明記）
- 楽観ロック競合（version 不一致）: UI からの誘発が困難
- 状態別サーバ拒否: UI から不可達（ボタン自体が出ない）。正本検証は BE/アクション層に委ねる（共通側と同判断）

### #512 同型回帰の採用
- `DeleteCustomerSellingPricePeriodCommand.ts:39-40` で空集約は親ごと削除する実装（共通の #512 修正と同じ B案）を確認済み。最終行削除→再登録の回帰テストを Chain A 末尾にミラーする
