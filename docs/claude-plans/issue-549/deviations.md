# Issue #549 実装の計画からの逸脱記録

計画（`e2e-delivery-location-selling-price-maintenance.md`）に対し、実装中に生じた差分を記録する。

## 逸脱1: 詳細「上書きなし正常メッセージ」の検証対象を D904×PRD877 から D902×PRD873 へ変更

- **元の計画内容**: Step 2 で、上書きなし正常表示（404 にならず「得意先別販売単価を、無ければ
  共通販売単価を適用します」）の検証に `D904×PRD877`（集約なし）を使う想定だった。
- **実際の実装内容**: 読取専用帯の `D902×PRD873`（上書きなし＋共通のみ）へ付け替えた。
- **逸脱の理由**: ファイル実行順は `crud`→`detail`（アルファベット順・`workers: 1` で直列）。
  crud の Chain A（D904×PRD877）は末尾の #512 回帰テストで将来行（¥7,000）を登録したまま削除せず
  終わる設計のため、後続の detail が同じ D904×PRD877 を「上書きなし（0 期間）」と期待すると衝突して
  失敗した（実行時に検出・修正）。上書きなしメッセージは納品先別上書きが 0 期間なら成立し、対象商品の
  素性に依存しないため、CRUD で変更されない読取専用帯 D902×PRD873 に付け替えるのが安全。得意先別 #509 が
  同メッセージの検証に読取専用帯 PRD863（共通のみ）を使ったのと同じ選択に揃えた。

## 逸脱2: seed の得意先別レーン投入を専用ヘルパー2本で実装（`insertCustomerPeriod`/`insertD904Period`）

- **元の計画内容**: Step 1 で `insertCustomerPeriod` ヘルパーと C903×PRD876 の customerSellingPrice
  集約作成を `seedDeliveryLocationSellingPrices` 内へ追加する、と記載。
- **実際の実装内容**: 記載どおり `insertCustomerPeriod`（C903 宛）を追加したうえで、保守帯 D904 への
  上書き期間 insert 用に `insertD904Period` クロージャも新設した（既存 `insertDeliveryLocationPeriod` は
  D902 を束縛しているため、宛先納品先が異なる D904 用に分けた）。
- **逸脱の理由**: 既存クロージャは D902 の id を閉じ込めており引数化されていない。最小改変で保守帯を
  足すには、D902 束縛の既存クロージャに手を触れず D904 用クロージャを並置するのが安全。計画の意図
  （関数を割らずに保守帯を追記する）とは整合し、方針転換ではない実装粒度の具体化。
