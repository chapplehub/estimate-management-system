# Issue #591: 開発環境での確認ができるデータを充実させる — 実装計画

## 概要

開発環境（seed-dev）のデータを、見積作成〜見積申請〜承認フローの手動確認・デモに耐える形へ拡充する。

前提となる構造判断として、dev から `prisma/seed-estimates.ts` / `prisma/seed-estimate-applications.ts` への依存を**完全に切断**し、両ファイルは e2e 専属とする（ADR-20260709-f2q）。dev は `prisma/seed-dev-data/` 配下に自前のフィクスチャモジュールを持つ。

拡充する内容（イシューの 5 項目に対応）:

1. **商品 40〜60 件**: 有効な価格保守対象商品へ共通販売単価＋原価を原則全付与。承認段階 4 閾値（10万/100万/1000万/3000万・税込）を現実的な数量で跨げる価格帯
2. **役割の横展開**: 4 段構造（課長→部長→本部長→社長）を維持したまま並行チェーン（製造系列など）を追加
3. **役割持ち従業員の拡充**: 営業系列役割に 2〜3 名のメンバー、階層別の固定ログインアカウント整備
4. **未申請の見積（ドラフト）**: 免除 3 理由＋承認段階 4 段の基本 7 件、閾値境界ペア、構造多様性数件
5. **多様な申請状態 40〜60 行**: 検索 8 軸すべてで弁別可能な分布、today 相対の申請日時

## 設計判断

### dev/e2e seed フィクスチャの共有可否
- A. 共有ファイル（seed-estimates.ts 等）に dev 拡充分を追記する
- B. dev 専用モジュールを新設しつつ共有部分は残す
- C. 完全分離: dev から共有 seed への依存を切り、e2e 専属化する
- 採用: C（dev＝網羅性・現実感と e2e＝断定可能性は最適化の方向が逆。詳細は ADR-20260709-f2q・起票済み）

### 共通販売単価の付与範囲
- A. 確認シナリオに必要な商品だけに付与する（現状の延長）
- B. 有効な価格保守対象商品に原則全付与し、保守画面確認用の例外（未設定・失効・期中改定・得意先別/納品先別上書き）を意図的に少数残す
- 採用: B（画面から自由に見積を組める土台。例外は「未設定」「失効」等の派生状態の確認台として明示的に設計する）

### 役割階層の拡張方向
- A. 縦に深くする（5 段以上）
- B. 4 段を維持して横展開（並行する承認チェーンを増やす）
- 採用: B（深さ 4 段は ADR-0063 の fail-fast 上限。チェーン形の多様性は横展開＋申請者の起点差で作る）

### チェーン不成立の検証用役割
- 上位役割エッジが欠けた役割を 1 件だけ置き、申請時のエラーパスを画面確認可能にする
- 役割名は「上位役割エッジが欠けている事実」がそのまま分かる命名（例: 「上位役割未設定 検証課長」）とする（ユーザー要望）

### 申請チェーン形の網羅方法
- A. ドラフト側でチェーン形ごとにデータを量産する
- B. ドラフトは金額帯・構成の網羅に徹し、チェーン形は「誰で申請するか」（operator の上位役割が起点）のログイン切替で網羅する
- 採用: B（チェーン形は申請者の上位役割で決まるため、同一ドラフトでも起点次第で 1〜4 段になる。対応表をドキュメント化する）

### 申請状態データの規模
- A. LIST_FETCH_LIMIT（1000 件）を超える量産でリミット挙動まで確認する
- B. 40〜60 行に抑え、各状態最低 5 件＋検索 8 軸（見積番号・得意先名・納品先名・状態 5 値・申請者名・承認待ち役割・申請日時レンジ・includeInactive）すべてで絞ると結果が変わる分布にする
- 採用: B（1000 件狙いは確認価値に対して保守コストが勝る）

### 申請日時の表現
- e2e で確立済みの today 相対シード（ADR-20260629-3x5・`daysAgo(n)`）を dev でも採用し、過去 90 日程度に分散。再シードすれば常に「今日基準」でレンジ検索を確認できる

### 決定性
- 新規データはすべて決定的（ランダム生成しない）とし、再シードのたびに同じ確認シナリオを再現可能にする。既存の従業員 2,000 名のランダム生成部分は本イシューのスコープ外として維持

### 旧共有 seed 由来の dev 見積 10 件の扱い
- 表示多様性（全部入り・改訂済み・セット群・REPAIR 等）は dev 専用セットの設計に再構成して吸収する（コードのコピーはしない）
- E2E のテスト手順に結合した関心事（S7 トグル用・申請ボタン出し分け用等）は dev に持ち込まない

### 見積番号帯
- dev 専用帯を予約し、e2e 予約帯（N9905xxx）・テスト予約帯（0000x/0100x）と衝突させない（例: N9906xxx / R9906xxx）。帯の一覧は `prisma/seed-dev-data/README.md` に記録する

### 実装機構
- 既存パターン踏襲のため判断不要: Factory＋Mapper＋seed 専用 PrismaClient で構築し、raw Prisma で金額を再実装しない（repository は @server/prisma シングルトンのため seed で使えない）。共有しないのはデータ定義であって設計方針ではない

### ドキュメント
- seed 完了メッセージ: 階層別ログインアカウント一覧（メール／役割／パスワード）と dev 見積番号帯の要点のみ
- `prisma/seed-dev-data/README.md`: 金額帯×承認段階の対応表、「どのユーザーで申請すると何段チェーンか」、検索 8 軸ごとの確認例のデータカタログ
- 用語: イシューの「見積もりドラフト」は正準語彙では「バリエーション申請状態が未申請の見積」を指す口語と整理し、README に明記（CONTEXT.md への新語追加はしない）

## ステップ

### Step 1: 役割・従業員の拡充（seed-dev.ts 内マスタ）
- 対象ファイル: `prisma/seed-dev.ts`
- 作業内容:
  - 役割の横展開（製造系列など並行チェーン追加）＋「上位役割未設定 検証課長」1 件
  - 営業系列役割への複数メンバー割当（2〜3 名）
  - 階層別固定ログインアカウント（課員・課長・部長・本部長・社長。弁別可能な決定的名前・従業員コード）
  - 部署と上位役割候補マップの整合更新
- コミットメッセージ: `feat: dev seedの役割・役割持ち従業員を拡充する (#591)`

### Step 2: 商品・価格の拡充（seed-dev.ts 内マスタ）
- 対象ファイル: `prisma/seed-dev.ts`（肥大するようなら `prisma/seed-dev-data/products.ts` へ切り出し）
- 作業内容:
  - 商品を 40〜60 件へ拡充（カテゴリ×単位×有効/無効×価格帯を網羅、承認段階を跨げる高額商品を含む）
  - 有効な価格保守対象商品へ共通販売単価＋原価を原則全付与
  - 意図的例外（未設定・失効・期中改定履歴・得意先別/納品先別上書き）を数点ずつ
- コミットメッセージ: `feat: dev seedの商品と販売単価・原価を拡充する (#591)`

### Step 3: dev 専用の未申請見積（ドラフト）モジュール新設
- 対象ファイル: `prisma/seed-dev-data/estimates.ts`（新規）、`prisma/seed-dev.ts`
- 作業内容:
  - dev 専用見積番号帯で、免除 3 理由＋承認段階 4 段の基本 7 件を作成
  - 各閾値の税込「直下」「ちょうど」境界ペア
  - 構造多様性（複数バリ・セット群・値引・無効バリ混在・改訂済み・REPAIR）
  - 作成者は固定課員アカウントに寄せる
- コミットメッセージ: `feat: dev専用の未申請見積シードを新設する (#591)`

### Step 4: dev 専用の申請状態モジュール新設
- 対象ファイル: `prisma/seed-dev-data/applications.ts`（新規）、`prisma/seed-dev.ts`
- 作業内容:
  - 5 状態×最低 5 件・計 40〜60 行、申請日時は today 相対で過去 90 日に分散
  - 申請者・承認待ち役割・得意先/納品先を検索 8 軸で弁別可能に分散
  - リッチケース（多段途中承認 PENDING・差戻→再申請 attempt 2・免除 3 理由・無効×差戻/取下）
- コミットメッセージ: `feat: dev専用の見積申請シードを新設する (#591)`

### Step 5: dev から共有 seed への依存切断
- 対象ファイル: `prisma/seed-dev.ts`、`prisma/seed-estimates.ts`、`prisma/seed-estimate-applications.ts`
- 作業内容:
  - `seed-dev.ts` から `seedEstimates` の import・呼び出しを除去し、seed-dev-data モジュール呼び出しへ全面切替
  - 共有 2 ファイルの「dev/e2e 双方で再利用」前提のコメントを e2e 専属へ書き換え（挙動は変えない）
- コミットメッセージ: `refactor: devからe2e用見積・申請seedへの依存を切断する (#591)`

### Step 6: データカタログと完了メッセージ
- 対象ファイル: `prisma/seed-dev-data/README.md`（新規）、`prisma/seed-dev.ts`
- 作業内容:
  - README: 番号帯・ログインアカウント一覧・金額帯×承認段階対応表・申請者別チェーン段数表・検索 8 軸の確認例・「ドラフト＝未申請」の用語注記
  - seed 完了メッセージへログインアカウント一覧と番号帯を追加
- コミットメッセージ: `docs: dev seedのデータカタログと完了メッセージを整備する (#591)`
