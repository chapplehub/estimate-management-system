# ADR-20260709-5ea: C4 内容編集は再解決契機とせず、既存明細の見積単価を itemId 突合で保全する

| 項目 | 値 |

| ステータス | 採用 |
| 起票日 | 2026-07-09 |
| 最終更新日 | 2026-07-09 |

## コンテキスト

#430 で見積単価の手入力を撤廃し、明細生成（商品選択）時に価格決定（#428・ADR-0064）で確定・固定する。これに伴い C1/C3/C4 のペイロード（ADR-0050 の JSON hidden field）から `unitPrice` を削除する。

ここで C4（バリ内容編集）に固有の問題が生じる。C4 のドメイン操作 `EstimateVariation.replaceContent` は「明細は識別子を保持せず新セットで全置換」する宣言的一括差替えであり、ペイロードの明細行も識別子を持たない（`productId` のみ）。単価がペイロードから消えると、**保存時に各行の単価をどこから得るか**を決めなければならない。数量やメモを直しただけの既存行にも、何らかの単価供給が必要になる。

CONTEXT.md「見積単価」は「確定値は見積ごとに保持され、商品マスタや販売単価マスタの改訂に追従しない」と定義し、ADR-0064 は再解決の契機を「明細追加／見積複製先生成／得意先改訂先生成／見積年月日・宛先変更」（実装は #431）に限定している。C4 の扱いはこの固定セマンティクスと正面から関わる。

## 検討した選択肢

### A. 保存時に全行を毎回再解決する（不採用）

ペイロードに識別子も単価も不要で、`replaceContent` の全置換モデルにそのまま乗る最もシンプルな案。しかし C4 保存が事実上の再解決契機になり、数量だけ直す編集でも触っていない行の単価がマスタ改定に追従して黙って変わりうる。

### B. 既存行は永続値を保全し、新規行・商品変更行のみ解決する（採用）

ペイロードの明細行に `itemId`（optional）を追加し、アプリケーション層が保存前に現行集約と突合する。

- `itemId` が対象バリエーションの現行明細と一致し、かつ `productId` が不変の行 → **永続化済みの単価**を引き継ぐ（クライアントが送る値ではない）
- `itemId` なし（新規行）、または `productId` が変わった行 → 明細生成として価格決定で解決する

ドメインの `replaceContent` は「解決済み単価を含むディスクリプタを受け取って全置換」のまま変えない。突合と単価供給はアプリケーション層の責務。

## 決定

C4 内容編集は再解決契機とせず、既存明細の見積単価は `itemId` 突合で永続値を保全する。新規行・商品変更行のみ明細生成として価格決定で解決する（B を採用）。

## 根拠

- **固定セマンティクスの保全**: A は CONTEXT.md「見積単価」の「マスタの改訂に追従しない」に反し、ADR-0064/#431 が4つに限定した再解決契機を裏口から増やす。単価が手入力できないぶん「価格が黙って変わる事故」を防ぐという ADR-0064 の UI 要件とも矛盾する。
- **クライアント値を信用しない構造**: B でもペイロードに単価は載せない。`itemId` は永続値の参照キーにすぎず、他見積の ID や偽造 ID は突合で一致せず「新規行」として再解決されるだけ——不一致が安全側（再解決）に倒れるため、追加の検証が要らない。
- **FE の追加コストが小さい**: FE の作業コピーは既に `rowId = itemId` で既存明細の識別子を保持しており、JSON に載せるだけで済む。
- **ドメイン不変**: 突合をアプリケーション層に置くことで、`replaceContent` の全置換モデル（granular 連打の O(N²) 再計算回避という設計意図）と `EstimateItem.create` の `unitPrice: Money` 受け口はそのまま生きる。

## 影響

- ペイロード形状（ADR-0050 の往復契約）に `itemId?: string` が加わる。用途は**単価保全の突合のみ**で、行の同一性保全（永続化の identity）には使わない——永続化は従来どおり旧行削除・新行挿入であり、`itemId` は保存のたびに新しくなる。この非対称は誤解しやすいので明記する。
- C4 で商品を入れ替えた行は単価が変わりうる（明細生成として解決されるため）。これは仕様であり、行内の商品入れ替え＝実質「削除＋追加」である。
- 数量・掛率・値引・メモの編集は何度保存しても単価に影響しない。マスタ改定と固定単価の乖離の可視化は別イシュー（#593）。
- CONTEXT.md「見積単価」に本ルール（内容編集は再解決契機ではない）を追記済み。
