# ADR-20260714-pv8: 改訂先生成では固定値引を持ち込まない（単価再解決に伴う絶対額クリア・複製と対称化）

## コンテキスト

得意先改訂（C7 `Estimate.reviseForCustomer`）は、改訂先明細の単価を得意先宛で再解決する（#431・単価は下がるのが通常）一方、固定値引（明細値引 `itemDiscount`・全体値引 `overallDiscount`）を改訂元から複写していた。得意先価格が改訂元の値引額を下回ると `値引後金額 < 0` となり、`LineItemAmountPolicy` / `EstimateAmountPolicy` の負値ガードが throw して**従来は改訂できた有効な見積が改訂不能になる**（Issue #598。PR #597 の自動レビューで検出）。

#431 の計画は「単価のみ解決・値引は改訂元から複写」を明示採用していたが、計画自体がこの相互作用（再解決で下がった単価 × 複写された絶対額値引）を分析していなかった。本 ADR はその判断を覆す。

なお対照として、見積複製（C6 `EstimateDuplicationService`）は当初から固定値引を付与しない（クリア）。「複製=クリア／改訂=複写」の非対称が本問題の火種だった。

## 検討した選択肢

### A. 値引クリア（採用）

改訂先には明細値引・全体値引とも付与しない。複製と対称になり、「単価再解決を伴う生成契機（複製・改訂）では率＝掛率のみ継承し、絶対額＝固定値引は持ち込まない」という単一原則に統合される。担当者は改訂先で得意先価格を基準に値引を入れ直す（改訂先の編集可能集合は掛率・明細値引・全体値引・メモ／ADR-0060・0064）。

### B. クランプ（不採用）

複写した値引を `discountedAmount` の範囲へ丸め、負値を 0 に留める。値引 500 が黙って実質 300 に切り詰められ、担当者から見えないデータ改変になる。「黙って 0 円にしない」を繰り返し明文化してきた方針（#431 のマップ欠落防御ほか）と真っ向から矛盾する。

### C. 複写維持＋事前検証（不採用）

複写を維持し、負値になる明細を列挙した専用エラーで改訂を拒否する。エラーが親切になっても行き止まりは行き止まり——改訂先はまだ存在しないため改訂先側で直せず、唯一の回避策は改訂元の値引を減らすことだが、改訂元は納品先へ提示済みの確定内容であり、改訂を通すために書き換えるのは本末転倒。実質的に改訂不能が残る。

## 決定

改訂先生成では固定値引（明細値引・全体値引）を改訂元から持ち込まず、クリアする（A を採用）。

## 根拠

- **絶対額は基準を失い、率は生き残る。** 固定値引は「その単価基準の明細・小計から何円引く」という判断であり、単価が得意先価格へ再解決された時点で額の根拠が消える。掛率は率なので基準が変わっても意味を保つ。#431 が複製で確立した「率は継承・絶対額はクリア」の論理は改訂にもそのまま成立する。
- **明細値引と全体値引で扱いを割らない。** 故障モードが同型（絶対額 × 下がった基準 → 負値ガード）で、片方だけ複写に残すと「絶対額なのに片方だけ持ち込む」新たな非対称を作る。
- **粗利スナップショットは無影響。** `deliveryPrice`（`RevisedEstimateItemDetail`）は改訂元の行金額 `finalAmount` のみから構成され、改訂先の値引をクリアしても §8.4 の粗利比較の基準は壊れない。
- **救済経路が業務的に自然。** 値引は改訂先で編集可能なため、担当者は得意先価格を見た上で「得意先基準の譲歩額」を改めて判断して入力できる。入れ忘れは粗利が多めに残る安全側の失敗。

## 影響

- CONTEXT.md「改訂先」の定義に固定値引クリアを追記済み。#431 計画の設計判断「掛率・値引は改訂元から複写」はこの部分に限り本 ADR が差し替える。
- `reviseForCustomer` は掛率・メモ・`deliveryPrice` スナップショットのみ改訂元から引き継ぎ、単価は再解決値、固定値引はゼロで生成する。
- 改訂直後の改訂先は値引なしのため、改訂元より行金額が高く見えるケースがありうる（得意先価格 > 納品先価格の逆転ケース等）。値引の再入力は担当者の判断に委ねる。
- 将来「改訂元の値引を改訂先へ引き継ぎたい」要件が出た場合は、絶対額の複写ではなく率への換算等、基準変更に耐える表現を検討すること（本 ADR の棄却理由がそのまま制約になる）。
