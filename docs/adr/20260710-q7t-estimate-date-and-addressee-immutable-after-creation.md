# ADR-20260710-q7t: 見積年月日・宛先は作成時確定の不変属性とし、変更契機の一斉再解決を廃する

| 項目 | 値 |
|---|---|
| ステータス | 採用（ADR-0064 の再解決契機から「見積年月日・宛先の変更」を撤回） |
| 起票日 | 2026-07-10 |
| 最終更新日 | 2026-07-10 |

## コンテキスト

#431 で価格決定の再解決契機（①見積複製先の生成／②得意先改訂先の生成／③見積年月日の変更／④宛先の変更）を実装する設計中、③④に固有の問題が見えた。

提出区分はバリエーション単位の属性であり（ADR-0045）、同一見積内に納品先宛と得意先宛のバリエーションが共存しうる。このとき例えば得意先だけを変更すると、得意先宛バリエーションの明細は解決入力が変わるが、納品先宛バリエーションの明細は入力（納品先・商品・見積年月日）が不変である。入力不変の明細まで「一斉に」再解決すると、その間の販売単価マスタ改定に黙って追従し、固定セマンティクス（CONTEXT「見積単価」の「マスタの改訂に追従しない」）を破る——ADR-20260709-5ea が C4 を再解決契機から外したのと同じ構図である。対象を「入力が変わった明細のみ」に精密化することは可能だが、複数バリエーション構成下での差分再解決はリスクと複雑性が高く、拒否時ロールバック・事前確認 UI（後続イシュー F）まで引き連れる。

一方、業務上バリエーションを作ってから見積年月日・宛先を変えるユースケースは極めてまれである。また空見積は存在できない（§C1: `Estimate.create` は0件を拒否し、最後の1バリエーションは削除できない）ため、「バリエーション存在時は変更不可」は**「作成後は常に変更不可」と等価**である。

## 検討した選択肢

### A. 作成時確定の不変属性化（採用）

見積年月日・得意先・納品先を見積作成時に確定する不変属性とし、変更する業務操作そのものを撤去する。`changeEstimateDate` / `changeCustomer` / `changeDeliveryLocation` の委譲鎖と C2（ヘッダ編集）の該当入力を除去する。再解決契機③④は消滅し、価格決定の（再）解決は「明細追加／見積複製先生成／得意先改訂先生成」の生成時3契機のみに縮約される。

### B. 変更契機の一斉再解決を実装する（#422・ADR-0064 の原案）（不採用）

契機③④で既存明細の単価を一斉再解決する。固定セマンティクスを守るには対象を「解決入力が実際に変わった明細のみ」（年月日変更→全明細、得意先変更→得意先宛バリのみ、納品先変更→納品先宛バリのみ）に絞る差分再解決が必要で、さらに1明細でも解決不能な場合の操作拒否・ロールバック、再解決前のユーザー確認 UI（後続 F）を伴う。

## 決定

見積年月日・得意先・納品先は見積作成時に確定する不変属性とし、変更操作を撤去する（A を採用）。誤入力の救済は、見積年月日は見積複製（複製時に指定可能・複製先生成の再解決が正しく働く）、宛先は新規作成のやり直しで行う。

## 根拠

- 極めてまれな操作のために、システムで最も危険な機構（既存明細の単価の一括書き換え）を実装・保守するのは割に合わない。
- 不変則「単価＝f(宛先, 商品, 見積年月日)」を「入力変更時の再解決」で追いかけるより、「入力の不変性」そのもので担保する方が強い。再解決は新しい見積資産の生成時にしか起きなくなり、「既存明細の単価が変わる」操作がシステムから消える。
- ADR-0045（提出区分＝バリエーション作成時確定の不変属性、宛先切替操作は存在しない）と同型の判断であり、一貫する。
- B 案は、一斉再解決なら固定セマンティクス違反（入力不変の明細がマスタ改定に追従）、差分再解決なら複雑性（対象絞り込み・ロールバック・確認 UI）を抱え、どちらに倒しても代償が大きい。

## 影響

- **誤入力の救済が非対称になる**: 見積年月日の間違いは複製で救済できるが、得意先・納品先の間違いは見積の作り直しになる（複製は宛先を複製元から継承するため）。必要になったら「複製時の宛先変更」（複製先生成の再解決契機に自然に乗る）を別イシューで検討する。
- `changeEstimateDate` / `changeCustomer` / `changeDeliveryLocation`（`Estimate.ts`）と C2（`UpdateEstimateCommand`・`EstimateHeaderForm`）の該当入力を撤去する（出荷済みコードの差し替え。ADR-0064 の単価ミューテータ撤去に前例）。C2 は「締切日・部署・税端数区分・修理詳細」の編集に縮小する。
- 税率は見積年月日から解決されるため自動的に固定される。税端数区分の改訂存在時ロック（`assertHeaderMutable`）は引き続き残る。
- ADR-0064 が定めた再解決契機4つのうち「見積年月日・宛先変更」を撤回し、契機は「明細追加／見積複製先生成／得意先改訂先生成」の3つに縮約（ADR-0064 に改訂注記）。#431 のスコープは複製先・改訂先生成時の再解決に縮小し、後続イシュー F（再解決前 UI 確認）は対象場面が消滅する。
- 「変更できる」ことを前提にした既存テスト（`UpdateEstimateCommand.test.ts` の得意先・見積年月日変更の正常系、`estimates-header-edit.e2e.ts` の得意先変更→納品先リセット、`Estimate.test.ts` の改訂時ヘッダガード系）の改修が必要。
- CONTEXT.md「価格決定」「得意先改訂」を本決定に合わせて更新済み。
